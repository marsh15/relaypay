# RelayPay v0.13.0 migration

v0.13.0 adds migration `0015_subscription_recovery`. Back up PostgreSQL, stop v0.12 API, worker,
poller, and console processes, upgrade the application, and run
`alembic -c migrations/relaypay/alembic.ini upgrade head` before restarting them. Existing payment,
ledger, evidence, agent-runtime, and dispute rows are never updated; the eight new recovery tables
start empty.

Run `python -m scripts.verify_m12_upgrade`, then all five Alembic drift checks from both an empty
database and a database upgraded through v0.12. Add the synthetic recovery-network service on port
8006 and set `RECOVERY_NETWORK_BASE_URL` for API and worker processes. The default policy permits at
most three retries and three consented messages within fourteen days.

This release includes only deterministic synthetic INR subscriptions, messages, and provider
outcomes. It performs no real payment retry, customer communication, hosting, or deployment.
