# Upgrade to v0.7.0

v0.7.0 has no database migration. Apply the release over a green v0.6.0 database and run the
normal Alembic upgrades; every schema remains at the v0.6.0 head.

The existing `/api/v1` operations, response bytes, errors, and idempotent replay behavior are
frozen. The additive `GET /api/v1/payment_intents` collection uses opaque `(createdAt,id)`
cursors. Cursors are filter-bound: changing `merchantReference` while reusing `after` returns
`400 INVALID_CURSOR`.

Operator routes remain session-authenticated under `/api/admin/v1` and environment-scoped where
they access tenant data. No deployment or hosting change is part of this release.
