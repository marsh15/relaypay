# Upgrade to RelayPay v0.5.0

## Before upgrading

- Back up the RelayPay database and confirm v0.4 migrations are at `0009_merchant_balances`.
- Provision the separate `bank` database and distinct `bank_app`/`bank_migrator` credentials.
- Keep API and workers stopped while the RelayPay schema migration runs.
- Continue using synthetic data only.

## Apply

```bash
uv run alembic -c migrations/relaypay/alembic.ini upgrade head
uv run alembic -c migrations/bank/alembic.ini upgrade head
uv run alembic -c migrations/relaypay/alembic.ini check
uv run alembic -c migrations/bank/alembic.ini check
```

Then start the bank service, API, worker, and poller. Existing `/api/v1` request and response
contracts are unchanged.

## Data behavior

Migration `0010_payouts` creates empty beneficiary, payout, reservation, attempt, evidence, history,
and event tables. It does not backfill or rewrite existing organisations, payments, journals,
postings, events, merchant accounts, or balance transactions. It only permits the new `PAYOUT`
journal and balance-transaction types.

The bank migration creates an independent synthetic account/effect/fault schema. No cross-database
foreign keys exist.

## Rollback

Do not downgrade after creating payout evidence or financial activity. Restore the pre-upgrade
backup instead. Downgrade is suitable only for a disposable empty sandbox.
