# RelayPay v0.14.0 migration

v0.14.0 adds migration `0016_settlement_intelligence`. Back up PostgreSQL, stop v0.13 API, worker,
poller, and console processes, upgrade the application, and run
`alembic -c migrations/relaypay/alembic.ini upgrade head` before restarting them. Existing payment,
ledger, evidence, agent-runtime, dispute, and recovery rows are never updated; the four new
settlement tables (`settlement_policies`, `settlement_forecasts`, `settlement_forecast_items`,
`settlement_questions`) start empty.

Run `python -m scripts.verify_m13_upgrade`, then all five Alembic drift checks from both an empty
database and a database upgraded through v0.13. No new services or environment variables are
required: settlement questions are answered synchronously by the API with the deterministic fake
provider by default, and the worker gains an hourly `record_settlement_forecasts` beat task. The
default policy is 17:00 Asia/Kolkata, T+1, weekends skipped; public holidays are out of scope.

This release includes only deterministic synthetic INR settlements, forecasts, and question
answers. It performs no real settlement, payout, hosting, or deployment.
