# RelayPay v0.11.0 migration

v0.11.0 adds migration `0013_agent_runtime`. Back up PostgreSQL, stop v0.10 workers, upgrade the
application, then run `alembic -c migrations/relaypay/alembic.ini upgrade head`. Start Redpanda before
the poller. Existing payment, journal, event, evidence, and `/api/v1` rows are not rewritten.

The migration adds the transactional business-event outbox, consumer deduplication, immutable
workflow/prompt/pricing/evaluation definitions, durable runs and leased steps, artifacts, approvals,
model/tool traces, and dead letters. It also adds `OPERATIONS_ANALYST` and `APPROVER` membership roles.

Run `alembic -c migrations/relaypay/alembic.ini check` against an empty database and a v0.10-upgraded
database. Redpanda is derived state: if unavailable, leave outbox rows unpublished and restart the
poller after recovery. Do not manually mark rows published.

No deployment, hosting, live model credential, real customer data, or real-money behavior is included.
