# RelayPay v1.0.0 migration

v1.0.0 adds **no database migration**. The portfolio analytics layer is query-only: it reads the
existing payment, dispute, subscription, agent-runtime, settlement, and risk-review tables and
populates in-memory Prometheus gauges. Back up PostgreSQL, stop v0.15 API, worker, poller, and
console processes, upgrade the application, and restart them. No `alembic upgrade` is required;
the Alembic drift check (`alembic ... check`) passes unchanged.

After upgrading:

- run `python -m scripts.run_evaluations` once against a migrated database; it records the
  `portfolio-v1` `EvaluationDataset` and a green `EvaluationRun` (the CI gate does this
  automatically);
- optionally run `make portfolio-demo` to execute the end-to-end synthetic journey against the
  local Compose stack;
- the new admin endpoint `GET /api/admin/v1/environments/{env}/analytics/portfolio` requires the
  existing `technical:read` permission and no new configuration;
- Grafana loads the six new `relaypay_portfolio_*` panels from the updated `operations.json`
  dashboard on next provisioning;
- `scripts/compare_live_providers.py` is optional and inert without `OPENAI_API_KEY`,
  `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`; it never runs in CI.

`/api/v1` wire compatibility, idempotency replay bytes, SDK behavior, and all prior
lost-response guarantees are unchanged.

This release includes only deterministic synthetic data and performs no real processing, hosting,
or deployment.
