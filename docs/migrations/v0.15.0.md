# RelayPay v0.15.0 migration

v0.15.0 adds migration `0017_merchant_risk_review`. Back up PostgreSQL, stop v0.14 API, worker,
poller, and console processes, upgrade the application, and run
`alembic -c migrations/relaypay/alembic.ini upgrade head` before restarting them. Existing payment,
ledger, evidence, agent-runtime, dispute, recovery, and settlement rows are never updated; the six
new risk-review tables (`onboarding_snapshots`, `risk_reviews`, `risk_review_versions`,
`risk_findings`, `risk_escalations`, `risk_annotations`) start empty.

Run `python -m scripts.verify_m14_upgrade`, then all five Alembic drift checks from both an empty
database and a database upgraded through v0.14. The new synthetic merchant-site service listens on
port 8007: add the `merchant-site` Compose service and set `RISK_SITE_BASE_URL` for API processes.
Risk reviews run synchronously with the deterministic fake findings provider by default; no worker
changes are required. The scoring model is version 1: completeness 0–20, domain 0–20, category and
content 0–30, pricing 0–15, suspicious claims 0–15 risk points.

This release includes only deterministic synthetic merchant sites and risk evidence. It performs no
real crawling, no merchant verification, no hosting, and no deployment.
