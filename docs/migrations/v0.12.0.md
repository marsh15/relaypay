# RelayPay v0.12.0 migration

v0.12.0 adds migration `0014_disputes`. Back up PostgreSQL, stop v0.11 API and worker processes,
upgrade the application, and run `alembic -c migrations/relaypay/alembic.ini upgrade head` before
restarting them. Existing payment, ledger, evidence, reconciliation, and agent-runtime rows are not
rewritten. The four new dispute tables start empty.

Run `python -m scripts.verify_m11_upgrade` and Alembic drift checks from both an empty schema and a
schema upgraded through v0.11. Package bytes are bounded to 20 MiB; budget database storage before
enabling large synthetic evaluation runs.

No production network, hosting, live customer data, or real submission is included.
