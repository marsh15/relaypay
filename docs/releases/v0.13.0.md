# RelayPay v0.13.0 — Subscription Recovery Agent

RelayPay v0.13.0 adds a consent-bound, terminal-safe synthetic subscription recovery workflow on the
shared PostgreSQL-authoritative agent runtime while preserving `/api/v1` and every earlier
lost-response guarantee.

Highlights:

- strict `recurring-payment.failed.v1` intake with payload digest verification and PII rejection;
- five deterministic failure classes with unknown outcomes restricted to provider lookup;
- immutable subscriptions, invoices, numbered payment attempts, policy versions, actions,
  communication records, and workflow-wide opt-outs;
- a code-reviewed fourteen-day policy capped at three retries and three consented messages;
- send-before-network payment/message records with status-only ambiguous recovery and one external
  effect per stable key;
- atomic terminal stops on success, opt-out, expiry, hard decline, and exhausted attempts;
- a responsive recovery queue and case console with explicit policy, consent, digest, and provider
  evidence;
- a fixed 30-case evaluation plus upgrade, dedupe, consent, race, limit, and terminal-safety gates.

This is synthetic INR portfolio software. It handles no real money, identity, customer, banking, or
messaging data. All provider and communication effects are deterministic mocks. No deployment or
hosting is included.
