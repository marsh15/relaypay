# RelayPay v0.7.0

RelayPay v0.7.0 freezes the merchant API contract and adds reproducible Python SDK generation.

## Included

- additive, tenant-isolated payment-intent collection with signed, opaque, filter-bound cursors;
- limits from 1–100 and stable `(createdAt,id)` ordering;
- committed v0.6 baseline and v0.7 OpenAPI JSON with an incompatible-change gate;
- private generated client from pinned `openapi-python-client` plus stable `relaypay_sdk` facade;
- typed API errors, TEST/LIVE_LIKE key validation, cursor iteration, retry guidance, and
  exact-byte webhook verification;
- committed response/error fixtures, runnable TEST examples, and error catalog.

## Compatibility and safety

Existing `/api/v1` operations, exact idempotent replay bytes, single-resource reads, error
envelopes, and `/api/admin/v1` session authentication remain unchanged. PostgreSQL remains the
authority and no network I/O was added inside a database transaction.

**Synthetic data only. RelayPay is not a payment processor. Never submit real payment,
bank-account, identity, or customer data.**

See `docs/migrations/v0.7.0.md`. This release does not deploy or host RelayPay.
